## Rules for structuring the backlog
1. Always make new issues as sub-issues of FoU Features (PI X-issue), not as a standalone without a parent-issue.
2. When starting an issue, add the issue into the roadmap with the start date being when beginning the issue. When closing an issue, adjust the issue in the roadmap so the end date matches.
3. As a general rule, if a issue has more than one team member working on it or the scope of assignment is considerable: create nested sub issue.
4. A team member should not work on more than 1 issue at a time. Can start a new one when the issue is in review.
5. Issue reviews:
   - One to two people who did not work on the task should review it together with the assignees.
   - For an issue to be eligible for acceptance of review, you must have completed the task it set out to do in a satisfactory manner.
   - Reviewer adds a comment before changing the issue to either done or reopening it.

---

## Issues Template
1. **Descriptive title** (Be specific)
2. **Issue description:** Describe in as much detail as necessary and possible for someone else to pick up the issue without needing to consult someone about it. Use text, images, and links if need be.
   - As a general rule, if a issue has more than one team member working on it or the scope of assignment is considerable: create nested sub issue.
   - If not, create tasks in checkboxes. These should act as a checklist and step-by-step requirement of what the issue entails, and will be used as referance in issue reviews.
3. **Priority:** P0 High, P1 Moderate, P2 Low.
   - Discuss with team what priority the **parent** issue should have. 
4. **Time estimate:** Number of days of work we believe a **sub** issue(s) will take.
   - Discuss with team for a more accurate estimate and for better team clarity.
5. **Add type:**
   - Task: A non coding task like planning, design, or documentation 
   - Feature: Coding task. Pi / sprint objectives 
   - Bug: Primarily coding - An unexpected problem or behaviour
6. **Add label:** Optionally add a label for further descriptiveness.
